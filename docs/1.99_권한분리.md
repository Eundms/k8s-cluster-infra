# 권한 분리 
## Bastion용 키와 Worker/Master용 키 따로 관리 
- Key A: Bastion만 접근 가능
- Key B: Master/Worker 접근용, 외부 노출 없음

```text
[Local PC]
   │
   └── SSH (Key A) ──▶ [Bastion Node (Public)]
                          │
                          └── SSH (Key B) ──▶ [Master / Worker (Private)]
```

## 역할별 접근제어

| 역할               | Bastion 접근 | kubeconfig 접근 (`~/.kube/config`)     | Cluster Admin 권한  | Namespace 접근  | 설명  |
| ----------------- | ---------- | ------------------------------------ | ----------------- | ---------------- | ----------------------------------------------------------------------------- |
| 🧑‍💻 백엔드 개발자    | ❌      | ❌                                | ❌                 | ✅ dev, staging   | - 자신 앱의 `kubectl logs`, `kubectl get pod`만 가능 - Helm chart 수정 가능 (자신의 환경만) |
| 👷‍♂️ DevOps          | ✅      | ✅ (`readonly` or `namespace-scoped`) | ❌ or 일부 제한        | ✅ All namespaces | - Jenkins 운영, Helm 배포 - ArgoCD 동기화, GitOps 구조 관리                   |
| ☁️ 클라우드 엔지니어  | ✅ (필수)     | ✅ (Full access)                      | ✅ (cluster-admin) | ✅ All            | - Terraform, Kubespray로 클러스터 구성 및 확장 - 보안 그룹, 노드 추가 등 제어  |
